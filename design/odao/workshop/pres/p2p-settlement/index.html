Gossip Group Mesh Topology

Peers self-organize into overlapping gossip groups of ~25. Bridge peers (amber) span multiple groups, relaying messages between them. Click "Send Message" to see propagation.

● Regular peer ● Bridge peer ── WebRTC channel

How Gossip Propagation Works

1. Author signs + hash-chains the message (Scuttle integrity, already built)

2. Trystero WebRTC delivers to all peers in the author's gossip group (~25 peers, <50ms)

3. Bridge peers forward to adjacent groups (another ~50ms hop)

4. 2-3 hops reach the entire swarm — 1000 peers in <200ms, 5000 in <400ms

Five Architectural Layers

1

Integrity Layer BUILT

Scuttle ed25519 signing + CBOR content addressing + SHA-256 hash chains. Every message is cryptographically signed and chained to its predecessor. Tamper-evident by construction.

src/lib/scuttle/ — 57 tests passing

2

Transport Layer PROPOSED

Trystero WebRTC mesh replaces Supabase polling. BitTorrent trackers handle peer discovery (signaling only). After SDP exchange, data flows peer-to-peer with end-to-end encryption. NAT traversal via ICE/STUN; TURN relay as fallback.

trystero — supports BT, Nostr, MQTT, Firebase strategies

3

Distribution Layer PROPOSED

BitTorrent-style swarming for message + file distribution. Every peer that receives a message becomes a seeder. Late joiners pull recent history from multiple peers in parallel. Files (images, attachments) are content-addressed and chunked across the swarm.

message received → verify signature → store locally → forward to neighbors → you are now a seeder
4

Ordering Layer DESIGN

Post-facto time settlement inspired by Solana's Proof of History. During live chat, messages display in approximate order (local clock + causal hints from hash chains). Periodically, the network produces a canonical ordering — settling time after the fact.

Economics Layer VISION

The settlement ledger IS the cryptocurrency. Users buy tokens via Stripe (fiat on-ramp). Tips are signed token transfers. Withdrawals process serially through the settlement queue. More network activity = faster settlement = natural incentive to participate.

Post-Facto Time Settlement

Like Solana settles time after the fact with Proof of History, the chat network doesn't need strict global ordering during live conversation. Messages display in approximate order, then the network produces a canonical settlement.

Why Post-Facto Works for Chat

Humans don't need global ordering in real-time. In a Discord server with 500 people typing, you see messages as they arrive. The display order is "good enough" from local timestamps + causal hints.

But the settlement ledger needs canonical ordering for token transfers (tips, withdrawals). You can't double-spend if every transfer is in a deterministic sequence.

So settle time like Solana does: let messages flow freely, then batch them into settlement blocks. The chat feels instant. The money settles shortly after.

The Settlement Token: GLY

The settlement ledger isn't just an ordering mechanism — it's a cryptocurrency. Users buy in via fiat, tip in tokens, and withdraw earned tokens back to fiat.

Buy In

Fiat → GLY

Stripe checkout (already built). Purchase GLY tokens at fixed rate. Tokens live in your ed25519 wallet.

Transact

GLY ↔ GLY

Tips are signed transfers between keypairs. Gossiped instantly, settled in next block. Revenue splits applied on-settlement.

Cash Out

GLY → Fiat

Withdrawal requests enter settlement queue. Processed serially (FIFO). Stripe Connect payout to creator bank account.

Why This Isn't Just In-App Currency

The settlement ledger is a real blockchain. Hash-chained, signed, validated by peers. Not a database column. Transfer history is immutable and independently verifiable.

The network processes it. Not a server. Active chatters are validators. Their devices verify transfers they witness. Quorum = settlement. The more people chatting, the faster money moves.

But it's fiat-backed. 1 GLY = fixed fiat value. No speculation. No exchange rate. The "crypto" is the settlement mechanism, not the economics. This is a utility token, not a security.

The Key Difference

Discord scales by buying more servers. Glyffiti Swarm scales by having more users. Every person who joins the chat adds bandwidth, storage, and validation capacity to the network. The chat gets faster and more reliable as it grows. Discord gets more expensive.

Honest Tradeoffs

●

Cold start. A chat with 3 people has no swarm advantage. Need Supabase relay as bootstrap until critical mass (~20+ peers).

●

Browser churn. Tabs close. Phones sleep. Peer availability is unpredictable. Settlement may slow when activity drops.

●

NAT traversal. ~15% of connections need TURN relay. Still need some infrastructure for signaling.

●

Token regulation. Even a fiat-backed utility token has regulatory surface area. Need legal review before launch.

Implementation Path

1

Add Trystero transport alongside Supabase relay

Keep Supabase as fallback. Route messages through WebRTC when peers are available. Measure delivery latency and reliability.

2

Implement gossip groups with bridge peers

Replace full-mesh with gossip groups of ~25. Auto-elect bridge peers based on connection quality and uptime. Cap vector clock at group size.

3

BitTorrent-style message + file swarming

Content-address files. Chunk across peers. Late joiners pull history from multiple seeders. Verify against hash chains.

4

Post-facto settlement blocks

Batch unsettled messages into canonical blocks. Elected settler per epoch. Block = merkle root + previous hash + validator sigs.
